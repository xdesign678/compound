# Compound 前端设计与交互体验走查报告

- 日期：2026-08-08
- 方式：10 组并行走查（代码审查 + Playwright 实际渲染验证，桌面 1440×900 / 移动 390×844，亮暗双主题）
- 范围：全部页面与组件——首页各视图（Wiki/资料/问答/活动/健康）、/recap、/review、/sync、/offline、设置与各模态框、命令面板、全局反馈组件
- 结论：**无 P0 阻断问题**；P1 共 14 项，P2 约 30 项。整体设计系统成熟度高，主要欠账集中在「错误态收尾」「暗色模式 token 泄漏」「对比度」三类。

## 一、跨页面共性问题（多组独立复现，优先级最高）

### P1-1 错误态与正常空态堆叠渲染，语义自相矛盾
- 位置：`components/ReviewQueue.tsx:372,586`、`components/SyncDashboard.tsx:258-338`（/sync、/review 两页同病）
- 现象：401/加载失败时，页面同时显示「需要认证」错误卡 **和**「当前没有待审核的条目」「尚未运行同步 + 立即同步按钮」等正常空态，CTA 点了也只会再失败。
- 建议：`error ? errorCard : listOrEmpty`，错误态下抑制空态与操作区，或对 CTA 置灰并说明原因。

### P1-2 错误文案把原始英文直接上屏
- 位置：`lib/store/ui-slice.ts:62-74`（`friendlyErrorMessage`）、`ReviewQueue.tsx:201,226`、`SelectionWikiProgress.tsx`、`GithubSyncModal.tsx:347`
- 现象：401 显示裸 "Unauthorized"；网络异常显示 "Failed to fetch"；GitHub 同步失败直接渲染 `{"error":"Unauthorized","requestId":"…"}` JSON 且重复展示两次。`friendlyErrorMessage` 只匹配含 "401" 子串的消息，覆盖不到纯文本错误。
- 建议：抛错统一携带 HTTP 状态码；映射表补 `Failed to fetch`/`NetworkError`；401 场景给出明确认证路径；原始错误收进「查看详情」折叠区。

### P1-3 亮色主题 `--text-tertiary` 对比度 2.74:1，远低于 WCAG AA 4.5:1
- 位置：`app/globals.css:23`（`#9a9890` on `#faf9f5`）
- 影响面极大：搜索占位符、卡片 meta、Wiki 目录项、复盘进度、思考步骤、空态文案等 11–15px 正文。`.list-load-more-hint` 还再叠 `opacity:0.6`（实际约 1.8:1）。品牌色 `--brand-clay #d97757` 作 13–14px 文字也只有约 3.0:1（"深入阅读"按钮、激活分类计数等）。
- 建议：tertiary 加深至约 `#75746e`（≈4.6:1）；hint 去掉二次降透明；正文级品牌色文字统一改用 `--brand-clay-text`（≈7:1，项目内已有先例）。

### P1-4 移动端 tab 切换丢失滚动位置，且停在"半路"
- 位置：`app/page.tsx:539`（`key={tab}` 重挂载 + 滚动容器复用）
- 实测：Wiki 滚到 900px → 切「问答」再回来停在 268px。新视图先以矮内容挂载导致 scrollTop 被钳制，比干脆归零更迷惑。
- 建议：按 tab 记住 scrollTop 并在内容就绪后恢复，或明确 scrollTo(0)。

### P1-5 暗色模式 token 作用域泄漏（多处）
- `/sync` toast：`.ops-toasts` 渲染在 `body` 直下，吃不到挂在页面类上的 `--ops-surface`，暗色下白底白字近乎隐形（`components/sync/Toast.tsx:47` + `ops-sync.css:2107`）。
- 设置面板移动端：`.settings-modal` 白色渐变叠在深色底上整体泛灰（`app/modals.css:7`，桌面板有覆盖、移动端没有）。
- 模型选择卡片：`.settings-model-group` 硬编码 `rgba(255,255,255,0.56)`，暗色下浅灰字压浅灰底，对比度约 1.2:1（`app/modals.css:310`）。
- modal 拖拽把手：`.modal-handle` 固定 `rgba(0,0,0,0.18)`，暗色下完全不可见（`components/modals.css:41`）。
- 建议：背景类 token 改用 `var(--bg-card)`/`color-mix` 派生或补 `.dark` 覆盖；ops token 提升到 `:root`。

### P1-6 移动端 /review、/sync 顶栏操作区布局塌陷（CSS 特异性 bug）
- 位置：`app/sync/ops-sync.css:1100` vs `:2262-2269`
- 实测：390px 下 `.ops-page .ops-topbar{align-items:center}`（0,2,0）覆盖断点内的 `stretch`，四个按钮缩成 87px 宽竖排长列，占首屏约 1/3。
- 建议：媒体查询内重置 `align-items:stretch` 或 `.ops-actions{width:100%}`。

## 二、各页面 P1 问题

### 详情页组
1. **嵌套弹层 Escape 穿透**：详情页内目录抽屉/编辑记录/删除确认的 Esc 处理未 `preventDefault()`，被全局钩子二次消费，按一次 Esc 连详情页一起关掉（`lib/hooks/useKeyboardShortcuts.ts:56` + `ConceptDetail.tsx:330-338`、`SourceDetail.tsx:374-383`）。局部处理加 `preventDefault()` 即可。
2. **分类 Wiki mermaid 图渲染成无文字空框**：mermaid v11 节点标签走 `foreignObject`，被 DOMPurify `FORBID_TAGS` 剥掉；`flowchart.htmlLabels:false` 在 v11 已废弃（`CategoryWikiDetail.tsx:129-162`）。改用顶层 `htmlLabels:false`。
3. **mermaid 图被普通交互永久冲掉**：打开"更新记录"触发正文重刷后 SVG 消失，`mermaidRenderedRef` 阻止重渲染，只能切分类重进（`CategoryWikiDetail.tsx:331-339`）。渲染逻辑应幂等可恢复。
4. **正文表格零样式且布局随访问路径不同**：无 `th/td` 规则，表格挤作一团；`.prose table{display:block}` 来自懒加载 CSS，先开概念页和直接开 Wiki 页渲染结果不同。补全局表格样式并消除路径依赖。

### Ask 问答
5. **移动端底部 sheet 遮罩失效**：`ask-view.css:811` 的 `display:none` 与 `globals.css:2145` 同特异性但后加载，390px 下遮罩不显示，弹层无模态感，点 tab 会"关弹层+切 tab"误触。把 `display:none` 收进 `min-width:1024px`。
6. **输入框双重焦点环**：全局 `:focus-visible` 直角橙框与卡片 `:focus-within` 圆角光晕叠加，鼠标点击也触发（`globals.css:146-164` vs `ask-view.css:734`）。textarea 上显式豁免。
7. **失败态同屏 3 个"重开"CTA**：失败卡内「重新提问＋新对话」+ 每条 AI 消息无条件「＋新对话」+ 顶部「重新开始」（`AskMessageList.tsx:124-130,184-193`）。`failedAnswer` 时跳过底部重复按钮。

### Wiki / 回顾
8. **WikiView 整套搜索是死代码**：`query` 状态、本地过滤、`searchWikiContext` 服务端检索、搜索空态全部存在，但没有任何输入框绑定 `setQuery`（`WikiView.tsx:73-162`）。补搜索框或删检索逻辑，二选一。
9. **/recap 桌面端翻页无可发现入口**：只有鼠标拖拽和未提示的 ←/→ 快捷键，无按钮、无手势说明（`RecapView.tsx:438-462`）。加 ←/→ 按钮或首次手势提示。

### 审阅与任务流
10. **SelectionWikiProgress 失败后永久"排队中"**：轮询失败把原始 JSON 上屏、无关闭按钮、每 1.5s 无限轮询且 localStorage 残留导致每次回首页重现（`SelectionWikiProgress.tsx:89-142`）。连续失败转 failed 态、给关闭按钮、清理 tracked run。

### 设置与模态
11. **移动端设置 sheet 滚动模型错误**：滚动容器是整个 sheet 而非 `.settings-main`，向下滚后标题/关闭/页签全部滚出视野（`app/modals.css:2149-2156`）。移动端改 `overflow:hidden`，让 `.settings-main` 成为唯一滚动区。
12. **GitHub 同步 401 排障文案误导**：未登录时仍提示「确认 GITHUB_TOKEN/GITHUB_REPO 环境变量」（`GithubSyncModal.tsx:573-577`）。按状态码区分文案。

### 全局反馈
13. **loading toast 失败后永久残留**：`showToast('AI 正在体检 Wiki…', true)` 无自动消失，失败时 error toast 与 spinner toast 同屏共存且无关闭按钮（`ui-slice.ts:231-255` + `Toast.tsx:45`）。`showErrorToast` 时清理 loading 项。
14. **HealthView 错误 banner 无出口**：深度检查启动失败后的内联横幅无重试无关闭，只能等下次成功（`HealthView.tsx:488-496`）。补重试/关闭或统一走 error toast。

## 三、P2 打磨项（按主题归并）

**对比度/可读性**
- 「一键修复」disabled 态 clay 底 + opacity .6，有效对比 <2:1 近乎隐形（HealthView / 活动页），改中性灰或无待办时不渲染。
- /sync 成功绿小字 `#5a856a` 约 4.0:1 不达 AA，补加深的 `-text` 变体（`ops-sync.css:1210`）。
- 导航关键文字 10.5–11px 偏小（tab 标签、header 副标题、kicker），建议提到 12px。
- sibling dimming（`:has(:hover)` 其他卡片半透明）未做触屏守卫，触屏点按后滞留（`globals.css:1878`），补 `@media(hover:hover)`。

**布局/组件一致性**
- 桌面端 `.modal-btn{width:100%}` 让「清空筛选」「加载更多」「回到主页」变成全宽灰横幅；列表/空态场景限宽居中。
- 「已显示 5/5」结尾 hint 条目不足一页时仍显示，且 `min-height:30vh` 在移动端制造大空白。
- 骨架屏与真实内容布局不一致（无水平 padding、卡片高度差 2 倍），加载完成瞬间跳动。
- SSR 首帧骨架不含 Header/TabBar，移动端首屏有底部栏 pop-in（`app/page.tsx:381-387`）。
- 桌面端"查看详情"两种范式并存：Wiki 概念弹遮罩浮层、资料走右侧分栏（`app/page.tsx:258-261`）。
- 桌面分栏分隔条鼠标热区仅 4px，透明 padding 扩到约 10px。
- 移动端一级分类 rail 可横滑但无渐变遮罩/peek 提示。
- /review 顶栏筛选按钮与导航链接混排无分组；空态文案不区分「待处理/全部」。
- Ask 桌面弹层按视口居中而非锚定内容列，错位约 160px；桌面空态垂直偏顶。
- Ask 移动端工具按钮触控 34px、工具行折行使输入卡偏高。
- 设置分段控件激活态跨断点漂移（桌面黑底/移动白底，移动暗色下几乎不可辨）。
- Ingest 弹窗主按钮在 1280×800 视口被折到屏外；桌面端拖拽把手显示不一致。
- 触控目标不统一：`.tc-dismiss-btn` 20px、`.ops-btn` 36px、filter-chip 40px，低于 44px 标准。
- toast 固定 `top:70px` 与流内 offline-banner 几何冲突；OfflineBanner 出现/消失推挤页面造成布局抖动。
- Toast 无退场动画；关闭图标三处三种写法（✕/×/x）。

**功能/逻辑**
- 资料卡片概念计数虚高：`where('sources').anyOf(ids)` 未加 `.distinct()`（卡片显示 10 > 全库 9），`SourcesView.tsx:80-90`。
- Wiki 入口「9 个待回顾」与复盘 deck 实际 8 张不一致，数字对不上。
- Wiki 目录 scroll-spy 不工作（observer 建立时锚点尚未渲染，`CategoryWikiDetail.tsx:371-389`）。
- 移动端分类 Wiki 页头"打开目录"是死按钮 + overlay aria-label 错报"资料详情"（`app/page.tsx:558-586`）；桌面端长文目录无入口。
- /sync「重试全部失败」按钮放在每个错误组内但重试的是整个运行，动作范围误导（`IssueCenter.tsx:64-73`）。
- Sparkline 成功柱实为 brand 橙（注释写绿色），失败柱 20% 透明度几乎不可见（`Sparkline.tsx:12-53`）。
- 选区浮窗按估计尺寸定位，遮挡选区后续正文（`ConceptDetail.tsx:48-49`）。
- 正文裸露 markdown：中英文混排 `**"…"**` 按 CommonMark 不构成强调，复盘卡直接显示星号（`lib/seed.ts` 内容 + `formatConceptBodyForDisplay`）。
- 事件流 success 徽章显示英文（`STATUS_TEXT` 缺 `success` 键）；「所有任务都已完成」在从未同步时不准确。
- ErrorBoundaryState 复制失败静默（注释声称的降级未实现）、深色只跟系统不跟应用 `.dark` 类。
- ImportProgress 错误色用品牌棕而非 error 红；「复制日志」无反馈；TaskCenter 列表项有 hover 无点击行为。
- 语言切 English 后设置主体仍是中文（GeneralTab/ModelTab 未接 i18n）；OfflineBanner 文案硬编码中文。

**可访问性**
- `role="tablist"` 内混入无 role 的「+」按钮（`TabBar.tsx:82-91`）；TabBar、ActivityView 子标签均缺方向键漫游/roving tabindex。
- Ask 内联 @ 面板的 listbox 语义挂在不获焦点的 div 上，应改 combobox 模式（`AskComposer.tsx:434-438`）。
- 无边框编辑器被全局焦点环套成整圈橙框，与"纸张感"设计冲突（用 `:where()` 降权或显式覆盖）。

**代码健康**
- `globals.css` 与 `globals-critical.css` 手工同步已漂移；类型阶梯/z-index token 被 10.5px、13.5px 等例外值绕过。
- `ops-sync.css` 多处重复/冲突定义与死代码（`.sync-v2-error` 两遍、`.ops-toast-close` 两遍、`review-pulse` 两遍、`.sync-v2-pause-chip` 死代码）。

## 四、做得好的方面（保持）

- 设计 token 体系完整（色板/字号/间距/圆角/动效/z-index/安全区），`prefers-reduced-motion`、`prefers-contrast`、全局 `:focus-visible` 环覆盖到位。

- 交互细节成熟：保存状态机（自动保存/草稿恢复/beforeunload）、乐观更新+撤销、焦点陷阱与焦点归还、命令面板键盘导航、复盘手势轴锁定。
- 空态文案与引导普遍完整（图标+标题+说明+CTA）。

## 五、建议修复顺序

1. **第一波（信任感）**：P1-1 错误/空态堆叠、P1-2 英文错误透传、二-10 永久排队、二-13 loading 残留——都是"系统反馈不可信"类问题。
2. **第二波（可读性）**：P1-3 对比度、P1-5 暗色泄漏、P1-6 移动端顶栏塌陷。
3. **第三波（核心交互）**：P1-4 滚动位置、详情页 Esc 穿透 + mermaid 双 bug + 表格样式、Ask 遮罩/焦点环/CTA 去重。
4. **第四波（打磨）**：P2 按主题批量收。
